PRE_DEPLOY_PARTIAL
  narrowed: STAGED_UPGRADE fires when a loader Buffer account receives an image that is not what is live, with bytecode hash, size, offset and staging authority; STAGED-NOOP fires when the bytes already match production; landing attributes the staged image by bytecode-hash match.

PDA_HOLDINGS_NOT_ENUMERATED
  narrowed: Routed value is still labelled as routed, never as custody. Additionally `--seeds` now derives PDAs from an operator-declared seed list, reads them in getMultipleAccounts chunks of up to 100, and sums lamports and raw token units per mint, with typed seed encodings (u8:1 vs the character "1") handled explicitly. The path is exercised against mainnet, not only against fixtures: `seeds-live.json` derives seven patterns, five resolve to accounts the chain named, one is a well-formed address holding nothing, one is an unresolvable `$user`, and the run summed 1,042,041,147,090 lamports and 986,570,981,170 raw units of `So1111…1112` in one batched call (`docs/live-seeds-2026-10-21.json`).
  remains: Only declared patterns are read. The seeds live in the deployment repo and a publisher who does not share them has, by construction, no observable custody — `unresolvedSeeds`, `accountsEmpty` and `complete:false` are reported so an absent figure is never shown as a zero one. No USD value is printed: there is no price oracle. And the figure is a snapshot: three of the five accounts in that live run belong to active traders, and a batched sum compared against individual reads a second later differed by 1,041,968 lamports — a trade, not a bug, which is why the exact-equality assertion in `test/seeds-live.test.ts` is made against ProgramData rent reserves, the accounts that cannot move except by upgrade.
  fix:     Publish the seed patterns in the deployment repo, or use an indexer/DAS API for programs that will not.
  tests:   test/seeds.test.ts, test/seeds-live.test.ts

HISTORY_RETENTION
  not a code problem: Dot cannot fix this and does not pretend to. Retention is a BigTable/provider decision; the only thing code can do is classify `-32015` as missing history instead of as a fetch error, and cap the tier on it.
  remains: Any graph built after the fact is built from what a node happened to keep. A program can look dependency-free because its integrators’ traces are gone.
  fix:     Deployment, not code: run Dot continuously and persist its own graph, or buy an archive-node endpoint. A `dot cache --warm` prefetch was proposed and is **not implemented in this build** — do not cite it.
  tests:   test/scout.test.ts

  remains: Nothing in the RPC response binds a transfer to a CPI leg. A router swap touching six accounts cannot be split, so no per-edge settlement figure exists to be computed.
  fix:     An instrumented node or an indexer that stores instruction-level balance diffs. Not a Dot feature.
  tests:   test/graph.test.ts

BLOCK_FETCH_AMPLIFICATION
  not a code problem: A block contains every transaction in the slot. Dot prices this explicitly: the plan prints callSavingRatio and byteAmplification together, refuses oversized blocks, and only batches when calls genuinely bind. The inputs are now measured, not guessed — `docs/calibrated-model-2026-10-21.json` came out of `dot calibrate` against mainnet (506 tx/block, 18,040 bytes per fetched transaction) and `test/calibrate.test.ts` asserts the plan uses it.
  remains: No encoding choice makes a block smaller than the block. Bandwidth-bound backfills need a filtered feed or an indexer, not a better getBlock call. The measurement is one endpoint on one day: block sizes vary by an order of magnitude between slots, so a deployment should re-run calibrate against its own provider.
  fix:     dot calibrate --rpc <url> replaces the labelled defaults with your endpoint’s real sizes; --cost-model <file> or DOT_COST_MODEL supplies it.
  tests:   test/ingest.test.ts, test/calibrate.test.ts

  fix:     More daily RPC, or a narrower --authority filter.
